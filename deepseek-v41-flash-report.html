DeepSeek V4.1-Flash 技术报告 · 深度解读

890 字节的上下文

技术报告的副标题是「把 KV Cache 压缩推向极限」，而它真正的赌注藏在这个数字里：每个 token 的 KV 缓存只要 890 字节——上一代 V4-Flash 的四分之一、V1 的四百三十七分之一。为了这个数字，DeepSeek 第一次放弃 decoder-only，把编码器请了回来；而后训练那一侧，官方承认算法零改动，全部赌注押在数据管线上。这份报告拆解两条主线，并回答一个问题：对一个正在给 V4-Flash 做安全 RL 后训练的团队，这份报告意味着什么。

两个数字最值得盯住。prefill 8B：Agent 任务的负载特征恰恰是输入重、输出轻——一次塞进去几万 token 的代码仓和工具文档，真正生成的可能只有几百 token。CED 把「理解输入」的开销单独定价，等于为 Agent 负载重写了成本公式。890 B：KV 缓存是长上下文服务里唯一随上下文长度线性膨胀的显存项，它决定了单卡能同时服务多少个长会话——压缩它就是扩大可服务的人群。

CED：编码器回来了架构

从 GPT 时代起，「编码器-解码器」几乎成了上个时代的词。V4.1-Flash 把它请回来，但装法是新的：解码器的全局 KV 不再由自己的隐状态逐层计算，而是从编码器末层隐状态一次性投影出来，全体解码层共享同一份。

为什么这一步是「范式」而不是「优化」？decoder-only 的每一次架构升级（MLA、稀疏注意力）都在回答「怎么把每层那份 KV 存得更省」，但「每层一份」这个前提从没被碰过。CED 碰的就是这个前提：KV 的来源从解码器自己的计算图里挪出去，交给编码器。代价是训练和推理系统都要为新拓扑重写——这不是免费的。

890 字节的三件套KV 压缩

890 B/token 不是单项技术的胜利，是一条压缩流水线：先去重（CSA2 层间共享）、再降精度（FP4 量化）、最后干脆不存储（SWA 有界重放）。三步各打一个浪费源。

三件套的顺序有讲究：去重必须放在量化前面——先把 40 份压成 1 份，再对这 1 份做 4 bit 量化，收益是乘法关系。如果反过来先量化再共享，每层的量化误差不同，层间共享的「同源性」就被破坏了。

四代压缩史×437

把三代数字放在一起才能看出这次跨越的尺度：389 KB → 3.5 KB → 890 B，累计 437 倍。前一次跨越靠的是「注意力算法」（稀疏化），这一次靠的是「架构拓扑」（CED）——红利来源换了层。

四件新装备组件

CED 骨干之外，报告还有四件值得记住的装备：Engram 条件记忆、DSpark 投机解码、新 MoE 配置、原生多模态。它们不是并列的功能清单——四件全在服务同一个目标：让 1M 上下文在真实服务上经济可行。

训练配方：算法零改动管线

后训练部分报告写得毫不浪漫：SFT → RL → OPD，三段式定型为官方标准管线，「没有算法层面的修改，全部实质改动在数据管线」。翻译过来：算法红利吃完的这一代，胜负手是数据工程。

这条管线对我们这批做 RL 后训练的人是最直接的信号。此前 OPD 更多是 Thinking Machines Lab 那篇博客带火的研究话题，各家是否采纳、放在哪个阶段、和 RL 的先后关系都是开放的；现在 DeepSeek 给出了官方答案：RL 之后接 OPD 收尾——RL 拉开能力上限，OPD 把强模型的行为蒸馏回稳定分布，两者是接力不是替代。

成绩单：登顶与短板评测

对我们的四条启示落地

读完报告回到自己的工位。我们正在给 V4-Flash 做安全 RL 后训练，这份报告的每个数字几乎都能映射到自己身上：76.7 是我们的基线，88.1 是官方展示的天花板，中间 11.4 分的配方全部写在数据管线那一节里。

如果只带走一句话：V4.1-Flash 把「上下文很长」从旗舰模型的演示参数，变成了可以按字节精算的服务成本——而它给 Agent 能力上限留出的提升通道，不在架构里，在数据管线里。前者我们已经受益，后者正是我们在做的事。
