DeepSeek V4.1-Flash 技术报告 · 全文深度解读

890 字节的上下文

技术报告的副标题是「把 KV Cache 压缩推向极限」，而它真正的赌注藏在这个数字里：每个 token 的 KV 缓存只要 890 字节——上一代 V4-Flash 的四分之一、V1 的四百三十七分之一。为了这个数字，DeepSeek 第一次放弃 decoder-only 把编码器请了回来；而后训练那一侧更值得读：官方承认算法零改动，全部赌注押在数据管线上——任务合成工厂、百万沙箱平台 DSec、努力度条件化 RL，以及用 RL 训练多智能体协作本身。这份报告按 PDF 全文逐章拆解（51 页），并回答一个问题：对一个正在给 V4-Flash 做安全 RL 后训练的团队，它意味着什么。

两个数字最值得盯住。prefill 8B：Agent 任务的负载特征恰恰是输入重、输出轻——一次塞进去几万 token 的代码仓和工具文档，真正生成的可能只有几百 token。CED 把「理解输入」的开销单独定价，等于为 Agent 负载重写了成本公式。890 B：KV 缓存是长上下文服务里唯一随上下文长度线性膨胀的显存项，它决定了单卡能同时服务多少个长会话——压缩它就是扩大可服务的人群。

基座评测表里最反直觉的一行：MMLU-Pro 74.1、HumanEval 79.4、BigCodeBench 60.6——8B/16B 的激活打平甚至反超 1.6T/49B 的 V4-Pro。官方把功劳记在预训练数据管线上（下一章细说），这给「数据质量 × 架构效率」的组合拳做了最强背书。

CED：编码器回来了架构

从 GPT 时代起，「编码器-解码器」几乎成了上个时代的词。V4.1-Flash 把它请回来，但装法是新的：解码器的全局 KV 不再由自己的隐状态逐层计算，而是从编码器末层隐状态一次性投影出来，全体解码层共享同一份。

为什么这一步是「范式」而不是「优化」？decoder-only 的每一次架构升级（MLA、稀疏注意力）都在回答「怎么把每层那份 KV 存得更省」，但「每层一份」这个前提从没被碰过。CED 碰的就是这个前提：KV 的来源从解码器自己的计算图里挪出去，交给编码器。配套的部署设计也很彻底：Encoder-Prefill-Decode（EPD）三段独立扩缩容，Reuse 模式的层 prefill 只需 15 个 kernel、decode 只需 11 个——架构概念复杂，kernel 流反而前所未有地简洁。

890 字节的三件套KV 压缩

890 B/token 不是单项技术的胜利，是一条压缩流水线：先去重（CSA2 层间共享）、再降精度（FP4 量化）、最后干脆不存储（SWA 有界重放）。三步各打一个浪费源。

三件套的顺序有讲究：去重必须放在量化前面——先把 40 份压成 1 份，再对这 1 份做 4 bit 量化，收益是乘法关系。Decoder 侧的 Bounded Replay 还有个隐藏收益：解码器 prefill 被限制在 n_win 个 token 内，整个 prefill 计算量近乎减半——压缩存储的同时顺手压了计算。

四代压缩史×437

把三代数字放在一起才能看出这次跨越的尺度：389 KB → 3.5 KB → 890 B，累计 437 倍。前一次跨越靠的是「注意力算法」（稀疏化），这一次靠的是「架构拓扑」（CED）——红利来源换了层。

五件新装备组件

CED 骨干之外，报告还有五件值得记住的装备：Engram 条件记忆、DSpark 投机解码、Single-Pass mHC、原生多模态 ViT、Muon 时代训练配方。它们不是并列的功能清单——全在服务同一个目标：让 1M 上下文在真实服务上经济可行。

预训练：数据是第一生产力配方

基座 8B/16B 激活打平 1.6T 的 V4-Pro，官方把功劳记在数据上：过滤「信息增益有限」的模型生成内容（视为隐式重复）、按「语料间整体交互」而非单样本质量选数据、重新爬取多模态源。优化器也换血：线性层用 Muon，嵌入与输出头用 Sinkhorn 平衡更新。

任务合成工厂：让模型造自己的考题数据管线

后训练最核心的一节。每个任务被形式化为三元组（问题， 环境， 验证系统），质量沿两个维度评估——难度（非平凡）与正确性（三组件无致命缺陷）。用这两个维度当奖励信号，迭代训练模型自己构造更好的任务——「模型已开始展现构造自己训练任务的能力」，官方选择重注押这里。

两条产品线。通用 agent 管线：鼓励内部员工和外部伙伴把最新模型用进日常工作流（自愿回流交互数据），按观察到的真实接口批量制造 mock 工具——复刻输入格式、输出结构、API schema、行为约束，覆盖 SaaS、企业应用到专业业务后端；同时大规模收集失败案例，重建设备上下文、用户交互模式与失败条件，生成单轮/多轮环境，系统性重放失败、对着弱点做定向 RL。

异步 RL 基础设施：驯服长尾 rollout系统

RL 效率的第一瓶颈是 rollout 阶段的长尾样本。V4.1 的解法是一整套系统工程：rollout 与训练同机时分复用、全异步生成、sample 级调度发车——三大副作用（长度偏差、off-policy、跨 checkpoint）各配对策，再用模型合并把多个 RL run 的收益拼起来。

对我们这些跑 GRPO 的人，这一章几乎每段都能对号入座：CyberGym 的 E2E rollout 恰恰是典型的长尾负载（50 轮对话、分钟级执行），sample 级调度 + off-policy 比例上限 + 过期 token loss mask 三招都是现成可搬的；「模型合并跨 run 聚合收益」则给多 scaffold 训练（不同奖励 shaping、不同环境难度）提供了一条不增加单 run 长度的扩展轴。

DSec：百万沙箱与不守规矩的 agent平台

V4.1 的训练需求是百万级并发沙箱——瓶颈从模型转移到数据中心：扩展性、隔离、单机密度、以及对越来越能干的 agent 的行为管制。DSec（DeepSeek Elastic Compute）是专门为此造的生产级平台。

努力度旋钮：RL 训练出来的连续控制推理经济学

reasoning_effort 不是部署时的提示词技巧，是RL 训练阶段的显式条件信号：系统提示词写入 Reasoning Effort: {b}（b∈1..100），每个 (prompt, b) 独立成组算组相对优势，长度惩罚系数随 b 指数衰减——模型学到的是一整条成本-质量前沿。

Multi-Agent：用 RL 训练协作本身前沿

报告最后拿出的实验最超前：Agent Team 模式里，lead agent 异步孵化持久化队友、全队共享一个代码仓 checkout、靠持久邮箱和任务板协作——而「协作」本身是被 RL 训练出来的（任务绩效 + 协作奖励 − 派生延迟惩罚）。多智能体行为第一次进入主流后训练配方。

◆ 奖励机制拆解。整场 episode 只打一个标量分：R = 任务绩效 + 协作奖励 − 派生延迟。三个分量各锁一种失败模式，缺一个训练就歪：只有绩效，RL 会塌缩回单干（spawn 有风险有开销，永远学不出团队）；加了协作奖励，模型又发现「多委派多通信」白拿分，刷消息、为小事 spawn；派生延迟负责把这类「协作表演」原形毕露。三张图依次拆开：先看互锁结构，再算派生延迟，最后走完整条打分流水线。

这套奖励的本质目的可以一句话收束：教会模型「什么时候值得并行」的经济学决策。测试时算力有两根轴——串行深度（想得更久，现有 reasoning scaling）和并行宽度（分身同时干）——单 token 接一个 token 的串行轴快到头了，这份奖励设计买的是第二根轴。它也是「薄壳跑赢厚壳」那条发现的延续：连组队、分工、同步的编排逻辑本身，也从脚手架代码搬进了模型权重。回头看本章开头的评测曲线就不意外了：1 小时时限并行还没回本（13.59 vs 12.79），8–20 小时复利拉开（+9.7 / +4.7 分）——模型被精确训练去吃「时限越长、并行越赚」的区间。

对我们的六条启示落地

读完报告回到自己的工位。我们正在给 V4-Flash 做安全 RL 后训练，这份报告几乎每个章节都能映射到自己身上：76.7 是我们的基线，88.1 是官方展示的天花板，中间 11.4 分的配方写在任务合成工厂那一节里；而异步 RL 基础设施和 Multi-Agent 两章，直接就是我们的下一步可抄作业。

如果只带走一句话：V4.1-Flash 把「上下文很长」从旗舰模型的演示参数，变成了可以按字节精算的服务成本；而它给能力上限留出的三条提升通道——任务合成工厂、异步 RL 基础设施、多智能体协作训练——没有一条在模型架构里，全在训练系统里。这正是我们在做的事的坐标系。
